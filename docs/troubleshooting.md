# 故障排查

| 现象 | 检查和处理 |
| --- | --- |
| HTTP 能访问，ADB 不通 | HTTP 是普通 APK 的诊断通道；分别验证原生 `device` 和 `shell id` |
| `CERTIFICATE_UNKNOWN` | 传输已进入证书验证，但当前身份未被电视接受。核对实际密钥与配对机制；仅重试端口无法补足授权 |
| `unauthorized` | 先确认原项目密钥仍在，使用 `tvctl.py connect` 重连；更换了密钥才按首次授权处理，勿直接覆盖电视授权列表 |
| `adb connect` 退出码 0，但输出失败 | 以 `get-state` 精确返回 `device` 和 shell 回读为准 |
| 配对失败 | 只有电视明确给出六位码和配对端口时使用 `adb pair`；ADB 开关端口通常是连接端口 |
| `init` 提示配置存在 | 保留已有私钥；端口更新使用 `connect --port`，IP 更新使用控制台连接框或编辑 `target` |
| 端口又变了 | `adb tcpip 5555` 只设置当前运行服务；固件会拒绝持久属性写入。开机后重新发现并切换即可 |
| 自动恢复连接失败 | 检查开机、ADB 开关、同一网络、电视 IP；mDNS 只发现同一 IP 的服务，可手动传当前端口 |
| ADB 服务加载了其他密钥 | 已拒绝复用。检查当前状态目录的专用 socket，不要终止其他工具的 ADB 服务 |
| 本机 ADB 密钥不存在 | 恢复配置指定的原私钥，不要重新生成身份或删除配置；若原私钥已丢失，需要重新取得电视授权 |
| ADB 未提供密钥路径 | 安装 Android Platform Tools 37.0.1 或更高版本 |
| 诊断接口拒绝操作 | 核对电视页面的访问凭据、版本 9 和电脑控制开关。仅安装 APK 不代表授权操作已启用 |
| 恢复配置失败 | 保留原始计划，恢复网络，执行同一计划的 `authorize-restore`；不要用新计划覆盖旧备份 |
| APK 签名冲突 | 新旧 APK 必须同签名。自行构建版本的签名与其他发布者不同，不能覆盖 |
| 安装操作等待 | 控制台已使用上传后 `pm install -r`。记录实际安装器输出；不要用流式 ABB 安装结果推断成功 |
| 画面正常，桌面点击无效 | 核对客户端 5.0.1、项目服务端及活动包名 `com.tcl.cyberui`。关闭其他 UI 自动化连接后重试 |
| 拖动没有滚动桌面 | TCL 专用触摸路径只处理点击和防误触，桌面导航使用垂直滚轮或方向键 |
| 滚动仍有卡顿 | 先限定页面、分辨率和帧率；桌面专用路由只覆盖 TCL 主桌面。用实机脚本区分输入和视频到达 |
| 实时画面按钮找不到应用 | 将两个 `.app` 放在同一目录 |
| 迁移后应用无法运行 | 在目标电脑重新安装 Python、ADB 和 scrcpy 5.0.1 并构建，本地 `.app` 含解释器路径及 Homebrew 库依赖 |
| 电视待机后连接消失 | 先开机确认网络；当前工具不承诺网络唤醒能力 |

实时窗口日志位于 `~/Library/Logs/TVControl/scrcpy.log`。发布日志前去除设备身份、地址、文件路径和屏幕内容。CLI 的 `doctor` 只检查本机；`status` 只检查保存的目标；`connect` 可能改变电视运行中的 ADB 端口。

本机 ADB 服务使用独立 Unix socket，电视端仍连接 `5555`。普通终端直接运行 `adb` 通常访问本机 `5037` 服务，身份和连接列表与本项目独立。排查时统一使用 `python3 tools/tvctl.py adb ...`。
